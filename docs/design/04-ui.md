# SAGE UI: design spec

The person using this is a crop or ecosystem scientist. They are not a developer and don't think in runs, anchors or IR. They want three things: add papers, get the data out, and check the data quickly enough to trust it.

## References

- **Google Drive** for the home screen. It is a plain list of documents, with one "New" button top left and drop-anywhere upload.
- **Google Docs suggestions** for checking. Each extracted value is a suggestion card in the margin beside its highlight in the paper, with Accept, Edit and "Not in the paper". The top bar's mode switch (Docs' "Editing / Suggesting / Viewing") becomes **Check / Data / Read**. Docs' version history becomes the extraction history.
- **The look** is minimal and neutral: greys, a single sage accent, and colour otherwise only for status.

## Restraint

These override anything below that conflicts with them.

- **No pills, badges or chips anywhere.** That covers status pills, count badges, type tags, basis tags ("Inferred"), "changed" tags, key-hint chips and source chips drawn as pills. There are no status dots or rings either. A value that needs a look carries the amber tint its highlight has on the paper, a green check mark means looks good, and a reviewed item keeps a muted mark of the decision. The status word lives only in the tooltip and the `aria-label`. Counts are plain muted numbers beside their label.
- **As little text as possible.** No sentence explains a status, a field or a screen unless the user can't act without it. An Advanced setting shows its title only, and the schema description moves to a tooltip on an ⓘ. Empty states get one short line and one button. Problems show as a few words ("No coordinates in the paper"), never a paragraph.
- **Clean and quiet.** It has generous whitespace, few borders, and dividers only where they separate things. Cards show nothing until they're active.
- **Not another shadcn project.**
  - The shadcn primitives are restyled until they don't look default.
  - Icons come from **Phosphor** (`@phosphor-icons/react`): regular weight for controls, fill for status shapes. `lucide-react` is not a dependency.
  - Icons appear only where they replace words, not beside every label.
- **The logo** is final. It is a page with two text lines and a curved leaf over its corner (paper in, data out). The leaf has a flicked tip, a thin midrib and four small alternating veins. The SVG is `web/src/assets/sage-mark.svg`, which `components/logo.tsx` inlines. Its page and leaf use `currentColor` in the sage accent, and the leaf's knockout outline and veins use `var(--sage-mark-bg)`, which `logo.tsx` sets to `var(--canvas)`. The favicon, `web/public/favicon.svg`, hard-codes the light and dark colours and switches with `prefers-color-scheme`. The wordmark is lowercase "sage" in Inter 600 next to the mark.

## Screens

The app has two screens and one dialog. It has no sidebar, no command palette, no review inbox, no separate review page and no separate extraction page.

| Route | What it is |
|---|---|
| `/` | Home: the papers |
| `/papers/$paperId` | Paper. Search params: `mode=check\|data\|read` (default `check` once data exists or the run's items are loading, else `read`), `item=<recordId>`, `filter=all` to list every item in Check, not only those to check, `type=<record type>` for Data mode's tab, `run=<runId>` to view an older extraction, `zoom=<step>` for the PDF's zoom (absent at Fit page), `details=1` to open the This run drawer, `extract=1` to open the Extract dialog (not while a run is live), `continue=<runId>` to open the Continue dialog on that run, `stop=1` to open the Stop dialog, and `settings=1` to open Settings over the paper |
| `/settings` | Home with the Settings dialog open. Closing it goes back. On the Paper screen, ⚙ adds `settings=1` instead. |
| `/runs/$runId` | Redirect only. It goes to `/papers/<that run's paper>?run=<runId>&details=1`, so old links and CLI hand-offs still land somewhere useful. |

### Not found

A page for something that isn't there keeps the top bar, with "Papers / Not found" as the crumb, and says what is missing in one line. An unknown path reads "There's no page at this address", and an unknown `/runs/<runId>` reads "There's no such extraction". An unknown `/papers/<paperId>` shows the server's message. A `run=` that isn't one of the paper's extractions reads "This paper has no extraction <runId>". It is `NotFound` in `pages/paper.tsx`, which is also the router's `notFoundComponent`.

### Small screens

SAGE needs at least 768px of width (Tailwind's `md`). Checking a value means reading its highlight and its card side by side, and a phone has room for only one of them. So below that width a notice takes the place of every screen. There is no separate phone layout. The notice shows the leaf mark, "SAGE needs a bigger screen" and a **Copy link** button, so the same page can be opened on a laptop. The button reads "Copied" for a moment, and a failed copy shows a toast. It appears only where the browser allows clipboard access (https or localhost). The named queries live in `web/src/lib/media.ts`.

### Top bar (both screens)

- It is 56px tall. Left to right: the logo mark in sage and the lowercase "sage" wordmark in Inter 600, which links home, then the breadcrumb on the Paper screen ("Papers / <title>"), then a flexible gap, then the screen's own controls, then a ⚙ icon button that opens Settings.
- Home puts a search field, at most 440px wide, in the middle of the bar ("Search papers"). It filters the list by title and filename as you type. `/` focuses it and `Esc` leaves it. With no match the list reads "No papers match “…”". An empty library has no search field.
- When no API key is set, a slim strip under the bar reads "Add your Anthropic API key to start extracting." with an "Open settings" link. Otherwise it never shows.

### Home (`/`)

- The content column is 960px wide and centred.
- At the top sits the heading "Papers" in the display font, with a filled **Add papers** button on its right. An empty library shows its own drop zone instead (below).
- PDFs can be dropped anywhere on the page. While dragging, a full-page overlay reads "Drop to add". Files that aren't PDFs are named in a warning toast ("Skipped notes.txt: not a PDF"). While a file uploads, its row shows a spinner and the filename. Each file has its own result. One toast sums up the files added, for example "2 papers added, 1 already in your library". A file that can't be added gets its own error toast, "Couldn't add <file>", with the reason, and the others are still added. An upload that fails as a whole reads "Couldn't add: …".
- Each row is 64px tall and shows:
  - the paper title (fallback: filename), weight 600;
  - under it, in muted caption text, `filename · N pages`;
  - the status on the right, as plain text with no container, in a fixed-width column so every title truncates at the same place;
  - the time of the last activity;
  - a row ⋯ menu with Open, Extract again ("Extract" before the first extraction, disabled while one runs) and Download PDF.
- Clicking a row opens the paper. `j` and `k` move the row cursor, hovering a row moves it too, and `Enter` opens the row.
- The status shows exactly one of these, no longer than three words. It is muted text, except "N to check" in ink and "Failed" in the danger colour. Its data comes from `PaperSummary`, so the home row, the Paper screen and the CLI agree.
  - "Not extracted", plus an inline outline **Extract** button. That button starts an extraction with the default model and then opens the paper.
  - The step with a spinner, such as "Reading tables…" or "Extracting…". The step is never prefixed with "Extracting", which would say it twice.
  - "8 to check": data that still needs a look.
  - "All checked", with a check icon.
  - How the last extraction ended, when no extraction of the paper has data: "Stopped", "Hit its limit", "Nothing found" or "Failed". An inline **Extract again** starts an extraction with the default model and then opens the paper.
  - When data stands but a newer attempt failed or stopped, or the data's own extraction was stopped or hit its limit, the row shows the data's state with a small warning icon beside it. Its tooltip alone says why: "Last attempt failed", "Last attempt stopped", or "Stopped at the turn limit" (or cost limit).
- With no papers yet, the empty state is a large dashed drop zone with the leaf mark, the line "Drop papers here", and an **Add papers** button.

### Paper (`/papers/$paperId`)

- **Top bar, after the breadcrumb, in order:**
  - the mode switch (a segmented control: Check, Data, Read), then a thin divider, both only once data exists or the run's items are loading;
  - a **Runs** menu (a ghost button with a clock icon and a caret) with This run (the run's details) and a History submenu, then Extract again… ("Extract…" before the first extraction) and Continue with guidance…, which takes the carry-on wording below for an extraction that failed, stopped or ran out of budget. It is disabled when the extraction shown found nothing and can't be resumed. While a run is live, Stop extraction… takes the place of the last two;
  - **Export**, an outline button with a download icon and a caret. Its menu has "Curation workbook (Excel)", "Curation workbook (CSV)" and "Everything (JSON)", disabled until data exists, then a separator and "Original PDF". Sage fill is kept for starting work, so Export doesn't get it;
  - ⚙.
- **Status line (40px) under the top bar, only while there is something to act on.** With data shown and nothing else to say, there is no line. The count is in the margin header and on Home, and "Accept 26 good" is in the margin header (Check) or at the right of the tabs (Data). The line appears for:
  - **Extracting:** a thin progress bar runs along the top edge of the line, with the stage: "Starting…", "Reading the paper…", "Reading tables…", "Extracting…" or "Checking…". In Read mode on a window at least 1024px wide, the run docks beside the paper (below), so the line has no "Details" link. Anywhere else, a "Details" link opens the drawer. A "Stop" link asks before it stops the run, which keeps what it found. When it finishes, a toast says "Extraction finished: 34 items", and the screen switches to Check if the run found any. A run that didn't finish gets a toast instead, with its title ("Extraction failed", "Extraction stopped", or "Stopped at the turn limit" or cost limit), the reason and its carry-on action. Only a failure is an error toast. A stop the user asked for, or a limit, is a warning. Toasts sit at the bottom centre, and every toast has a × to close it.
  - **The data shown has an extraction that didn't finish behind it:** a newer attempt failed or stopped, or the data's own extraction was stopped or hit its limit. The line shows a warning icon and "Last attempt failed", "Last attempt stopped", or "Stopped at the turn limit" (or cost limit), then its carry-on action and "Details". It ends with a ×. Closing it hides that run's alert for good in this browser (localStorage), on Home as well, so a scientist can use the data as it is. A newer run that ends badly alerts again.
  - **Older extraction picked from History:** "Oct 12, 4:10 PM" and "Back to latest". When the extraction that stands for the paper is older than the one shown, the link reads "Back to Oct 10, 9:02 AM" instead.
- **Carrying on.** One rule, `carryOnLabel` in `lib/format.ts`, words the action that carries an ended run on, wherever it shows: the status line, the toast, the Extract card and the drawer's footer.
  - A run that failed or was stopped: "Resume…", which opens the Continue dialog as "Resume extraction".
  - A run that ran out of budget with items: "Continue", which continues it at once.
  - A run that ended with no items and can't be resumed (it finished with nothing, or ran out of budget with nothing): "Extract again…", which opens the Extract dialog and closes the drawer.
  - A run that finished with items: "Continue…", which opens the Continue dialog. Only the drawer's footer offers it.
  - The reason shown with it is the run's error in a few words when it has one, else "34 items so far", or "Nothing found yet" when the run kept nothing.
- **One scrollbar per screen.** Home scrolls the window; the Paper screen scrolls one pane under the top bar (in Data mode the side sheet beside it scrolls its own fields). Nothing scrolls inside something that scrolls. A box that must scroll sideways inside the pane, like a wide table in a card, hides its bar and shades its right edge while more columns sit past it. Scrollbars are thin, on a transparent track.
- **Never extracted.** The paper shows in Read mode, with a small centred card over its top: a model select (defaults to the Settings model, e.g. "Haiku 5.5") and a filled **Extract data** button. There is no other text.
- **Ended short with no data.** The same card shows the run's title ("Extraction failed", "Extraction stopped", or "Stopped at the turn limit" or cost limit), the reason in a few words, and its carry-on action and "Details". A × closes the card for that run, and the plain Extract card takes its place. A run that finished with no items shows the plain Extract card.

#### Check mode

Google Docs-style suggestion cards in the margin, pinned beside their highlights. There is no stacked side panel. These rules cover the edge cases.

- **Layout.** The PDF is on the left and a 380px margin is on its right, inside the same scroll container, so cards scroll with the paper. A sticky header sits at the top of the margin and holds three things:
  - a thin progress bar with "12 of 74 reviewed";
  - the To check / All filter;
  - an **Accept 26 good** text button, hidden when there are none.
- **Pinning.** Each card's top lines up with the top of its first highlight. Cards are ordered by page, then y, then column (left before right), so two-column papers read correctly. Layout is recomputed whenever the zoom, the filter or an expanded card's height changes.
- **Collision**, as in the Docs comment layout:
  - The active card snaps exactly to its highlight.
  - Cards above it shift up and cards below shift down, with an 8px gap.
  - Movement animates for 150ms and respects reduced motion.
  - The margin grows past the last page if it has to, and never overlaps.
- **Table clusters.**
  - When three or more items anchor inside one table, one cluster card replaces them, pinned to the table's top: "Table 1 · 22 values". Expanding it shows the compact grid shaped like the paper's table, with per-cell status, "Accept table" and arrow keys. A grid wider than the margin scrolls sideways while its row-key and label columns stay pinned.
  - This keeps a small table from pulling a tall stack of cards into the margin.
  - Items on prose get a card each, however close together they sit. They are never grouped under a count, because a title like "3 values" says nothing about what is inside.
- **Items with no location in the paper** form one "Not located" cluster at the top of the margin, under the header. Expanded, it lists its items with "Accept all".
- **Collapsed cards** are a single 32px line with the status mark, the label, and the problem in muted text. The mark is a check for looks good, an empty slot for the rest, and the review's icon once reviewed. They have no border, and a surface background only on hover.
- **The active card** expands with a 1px accent border and shows the same item panel as Data mode's side sheet (below): one collapsible row per field, with the fields that need a check open, then **Accept**, **Edit** and **Not in the paper**. "Not in the paper" opens an optional note with its own confirm and Cancel. A reviewed item shows its decision with **Change** in place of the buttons. An item has one editor, wherever the user opens it.
- **Linked hover.** Hovering a card emphasises its highlights, and hovering a highlight emphasises its card.
- **Navigation.**
  - `j`/`k` move to the next or previous item in document order, within the filter.
  - Each move scrolls the pane so the highlight and its open card are centred together in the room below the margin's header. A pair too tall for that room shows from its top, with the highlight kept in view. A tall table follows its active cell. Only a move scrolls; zooming never does.
  - After an action, the next item still to check becomes active.
  - When nothing is left, the header reads "All checked", with an Export button, above the filter.
- **Zoom.** The PDF opens at Fit page: the room beside the margin, up to 1040px wide. Moving between items never changes the zoom, so the page never resizes under the reader. The reader zooms by hand, in steps from 50% to 250%:
  - `Ctrl` or `⌘` with the wheel, or a trackpad pinch, zooms at the pointer, keeping the point under it still;
  - `+` and `-` zoom at the middle of the pane;
  - `0`, or "Fit page", floating in the top-right corner of the PDF pane while zoomed, goes back to Fit page.
  - The zoom lives in the URL (`?zoom=1.5`), so it holds across items, modes and reloads. Cards re-pin at the new coordinates.
  - A page wider than the pane scrolls sideways under the margin, which stays pinned to the right edge. Moving to an item scrolls sideways too when its highlight is out of view.
  - Only the pages near the middle of the pane draw. The rest keep their size, blank, until scrolled to.
- **Highlights.** The active item's highlights are at full strength and the rest fade. Amber means check this, sage-tinted means looks good or reviewed as accepted or edited, a dashed grey outline means missing, and a fainter dashed outline means "Not in the paper".
  - **The quoted words, not the paragraph.** For the active item, the lines its quotes cover are tinted at full strength, and its block keeps only a faint wash and a thin outline for context. Other items keep one faded box per block, so the page doesn't fill with marks. A table cell already has its own box. A quote the server couldn't place, and a value that is guessed rather than quoted, draw as the whole block.
- **Keys:**
  - `j`/`k` move between items;
  - `a` accepts, `e` edits, `r` is "Not in the paper", `c` changes a reviewed item, and `Esc` cancels an edit;
  - `Shift+A` accepts a whole cluster;
  - arrow keys move between cells inside a table cluster;
  - `/` switches the filter;
  - `+`, `-` and `0` zoom, as above;
  - `?` shows help.
  - A one-line key hint, "j k move · a accept · e edit · r not in paper", shows at the bottom of the margin until the user has made ten keyboard actions (counted in localStorage under `sage.key-hint.uses`).
- **Accept good** accepts every "Looks good" item that has no review yet, in one call (`core.accept_looks_good`). A toast says "26 accepted". Since the latest review wins, any of those can still be edited or rejected later.

#### Data mode

- Data mode is a full-width table view with no PDF. Tabs across the top list the item types that have data, each with a plain count, in this order: Citation, Studies, Sites, Species, Crops, Treatments, Variables, Methods, Management, Comparisons, Observations, Coverage. The open tab lives in `type=`. When the tabs don't fit, they scroll sideways inside their row. The page never scrolls sideways.
- Each tab is a table with one row per item and one column per field, and cell values use tabular numbers. Observations use fixed columns instead: Variable, Treatment, Value, Statistic, When and Source. Clicking a column header sorts by it.
  - A cell that needs a check is tinted amber, and a missing cell shows a muted dash. Wide tables truncate their cells to fit the pane; they never scroll sideways.
  - A reviewed row shows its mark in the first column.
- **The row is the only click target. Cells are not individually clickable**, because the user called per-cell targets "very bad UX". Clicking a row, or pressing `Enter` or `Space`, opens a 440px side sheet for that item, and `j`/`k` move between rows with the sheet following along. `Esc` closes the sheet and returns focus to the row.
- **The side sheet shows every field of the row, not a summary**, as a list of collapsible sections, one per field:
  - The section header shows the field name and its value, tinted amber when it needs a check.
  - Fields that need a check are expanded by default, and the rest are collapsed.
  - An expanded field shows its value (editable in place), the problem in a few words, the quote or quotes with the matching words highlighted, the basis as one muted word ("Quoted", "Calculated" or "Inferred"), and a "Page 3" link that switches to Check mode with this item active.
  - The sheet's footer holds Accept, Edit and Not in the paper for the whole item. Edit opens the first field that needs a check and selects its text, and Enter saves.
  - This panel is the one the Check card uses. While it is open, `a`, `e`, `r` and `c` work in Data mode too.
- Observations use the same row-and-sheet rule.

#### Read mode

- The PDF is centred with the highlights on and no margin.
- Hovering a highlight shows a tooltip with the item's label. Clicking one switches to Check mode with that item active.

#### Live extraction dock

- While a run is live and the paper is in Read mode, on a window at least 1024px wide, the run's details sit in a 440px column to the right of the paper. A paper's first extraction always runs in Read mode. The column has the drawer's header and tabs (below) under the title "This run", with no backdrop and no footer. The PDF fits the width left beside it, so the reader can read the paper while the run works.
- On a narrower window there isn't room for both, so the status line keeps its "Details" link to the drawer.
- The column has no close button. It goes when the run ends. If the run found items, the screen switches to Check and the review cards take its place. If it ended short with nothing, the Extract card says how it ended over a paper with no data, and the status line's alert shows over older data. A run that finished with no items leaves the plain Extract card.
- While the column shows, `details=1` doesn't open the drawer over it, and the Runs menu disables This run.

#### This run drawer (Runs › This run, or `details=1`)

- It is a right-side sheet, 480px wide. A fixed header holds the status and start time, then model and effort, time, cost against the limit, and turns against the limit in a two-by-two grid, then a segmented control with three tabs: **Activity** (the default, below), **Usage** and **Log**.
- **Activity** is one scrolling timeline, with one fold per step (Read paper, Tables, Extract, Check, Done). Each fold shows its done, running, failed or stopped state and how long it took. The running step, a failed or stopped step, and Done with the model's summary start open. The others start folded.
- The states:
  - **Starting:** Read paper shows as running before the log has anything in it.
  - **Failed:** the failed step holds the error. Nothing logged after the error (the salvage settle) shows until a resume. The header shows the error only when the log doesn't hold it.
  - **Interrupted** (stopped, or the worker died): the step it was on shows as stopped, timed up to the last thing the run logged. After a Stop, the Check step that settles what the run kept shows as done after it. A resume clears the stopped step and every step after it.
  - **Out of budget:** Done shows as stopped, with "Stopped at the turn limit" or "Stopped at the cost limit".
  - **Resumed:** each step the resume runs again replaces its lines, except Extract, whose turns carry across attempts, and the run's opening lines ("Continued from an earlier extraction" and its guidance). "Resumed with Haiku 5.5", with the guidance it was given, opens the new attempt at the top of its Extract step, after the earlier attempt's turns. A turn the old worker never finished drops out, and each step's time is its latest attempt.
- Inside Extract, each model turn shows a folded "Thinking", what the model said in plain text, one short line per action ("Wrote 5 Treatments", "Expanded Table 1 into 16 observations", with the figures from the tool result's `tally`, or from its text in a log written before tallies), and the checker's errors on that turn folded as "N problems". Each problem shows the field and the first sentence of the error. A turn still waiting on the model shows "Thinking" with a running timer.
- While the run is live the feed follows the newest line. Scrolling up or opening a fold stops that and shows a "Latest" button, which jumps back down and follows again. The page applies events once per frame, so replaying a long run doesn't render once per event.
- **Usage** holds every number the run recorded, which keeps the numbers out of Activity.
  - Budget: cost and turns as meters against their limits. The fill is sage, amber from 80% and red at the limit.
  - Tokens: input, output, the share read from the cache, and requests. Below them, one bar splits all input into cache read, cache write and uncached, with a legend that gives each count and share.
  - Under the same heading, input per turn: one column per extraction request, split the same way, so a turn that broke the cache stands out as a tall cache write. A small mark under a column flags a turn the API reported as a cache miss. Hovering or focusing a column shows its numbers and the miss reason. "Every turn" opens the same numbers as a table.
  - By pass: requests, input, cache read and write, output and cost for the extraction agent and the table transcription side by side, with each one's model.
  - Run: the run and paper ids, status, effort, both full model ids, created, started and finished times, resumes, item counts, the run it continues and its guidance.
  - The input split uses one sage ramp, with cache reads in the strongest shade, checked against the surface in both themes.
- **Log** shows the raw events. A bar pinned to its top gives the event count and a **Copy** button. Copy puts the whole log on the clipboard as JSON Lines, one line per event as in `events.jsonl`, and reads "Copied" for a moment. If the copy fails, a toast reads "Couldn't copy the log".
- The footer holds the run's carry-on action (above). The drawer hides it while the run is live, and the dock has none.
- An extraction started from the CLI streams here the same way.
- The drawer and the dock are the only places tokens may appear.

#### History (Runs › History)

- It is a 360px submenu of the paper's extractions, newest first, styled like the menu it opens from, and disabled when there are none. Each row shows the time, model, outcome and "N items" or "No data". A check marks the extraction shown.
- A row whose extraction has guidance has a third line with it.
- Picking one shows that extraction's data (`run=`), and the status line says so.

#### Extract again… dialog

- The dialog, titled "Extract data", holds a model select ("Haiku 5.5", "Sonnet 5.5" and "Opus 5.5", with the hints "fastest, cheapest", "balanced" and "most careful"), a "Thinking effort" select under "More options", the cost limit line ("Stops at $1.00"), and a filled **Extract data** button.
- It starts the extraction, closes, and the status line takes over. It doesn't open while a run is live.

#### Continue dialog (Runs › Continue with guidance…, a "Resume…" action, or the drawer's footer)

- On an extraction that failed or was stopped, it is "Resume extraction", which picks the same run up again. On any other, it is "Continue extraction". A new extraction starts from this one's data with a budget of its own, and this one stays as it is. One that ran out of budget is continued, not resumed, since a resume shares the budget it used up.
- It holds "What should it add or fix?" (required to continue a finished extraction, optional otherwise), an "Include my review notes" switch, on by default, and, to continue, the model and effort under "More options", defaulting to the earlier run's. The button reads **Resume** or **Continue**. ⌘↩ or Ctrl+↩ in the text box submits.
- The drawer's feed marks the start with "Continued from an earlier extraction" and the guidance.

#### Stop dialog

- "Stop this extraction?" with Keep going and Stop. The run settles what it has and reads as interrupted, and Resume carries it on.

### Settings dialog (`/settings`, or ⚙)

- The dialog is centred and 560px wide, with sections in this order:
  1. **Anthropic API key.**
     - **When a key is saved,** it shows as text ("••••abcd") with **Change**, **Test** and **Remove** text buttons. **Change** opens an empty password input ("sk-ant-…"). The typed key joins the form, so the footer Save saves it with everything else. A quiet ✕ beside the input keeps the saved key instead. **Remove** deletes the saved key at once, without Save.
     - **When no key is saved,** the input shows immediately.
     - The field never looks read-only. A saved key shown only as placeholder text reads as uneditable.
     - **Test** shows "Works" with a check, or a short error, inline.
  2. **Model.** The extraction model as a select with friendly names.
  3. **Cost limit per paper.** A dollar input.
  4. **Appearance.** System, Light or Dark, as a segmented control.
  5. **Advanced**, collapsed by default. It lists every other `Settings` field under a heading per group, taken from each field's `group` in field order ("Other" for a field with none). Each field shows its title, an ⓘ tooltip holding the description, and a small reset icon ("Back to default") that appears only when the value differs from the default.
- A field set by an environment variable is read-only, with "Set by <variable>" beside it, for example `SAGE_MAX_TURNS` or `ANTHROPIC_API_KEY`.
- The footer has Cancel and a filled **Save**. Save writes only the changed fields, shows "Saved" as a toast, and closes. With nothing changed it just closes.
- The form skips the browser's own checks (`noValidate`), so every invalid value shows the server's message under its field. Editing a field clears its error. A Save that fails on an Advanced field opens Advanced, which stays open while the field is fixed. An error that names no field shows in the footer.
- Every setting is editable here, and edits take effect for the next extraction.

## Vocabulary on screen

| Internal | On screen |
|---|---|
| run | extraction, except in the **Runs** menu and the **This run** drawer and dock |
| record, entity | data item, or the entity name ("Site", "Observation") |
| anchor `p7.t1.r3.c2` | "Table 1, row 3, Yield" or "Page 4", as plain link text, never a chip |
| basis stated / derived / inferred | not on collapsed cards. The item panel (the active card and Data mode's sheet) shows it as one muted word: "Quoted" / "Calculated" / "Inferred" |
| status verified / flagged / unresolved | "Looks good" / "Check this" / "Missing" |
| review accept / edit / reject | "Accepted" / "Edited" / "Not in the paper" |
| unresolved cause | a plain sentence, e.g. "Only shown in a figure" |
| run status queued / running / interrupted | "Starting" / "Extracting" / "Interrupted" |
| budget_exhausted | "Stopped at the turn limit" or "Stopped at the cost limit", whichever limit stopped it |
| tokens | never shown outside the Usage tab of the This run drawer and dock. Cost is shown in dollars. |

Use sentence case everywhere. Never use all-caps labels.

## Look: minimal neutral

The look is neutral greys with a single sage accent, and colour otherwise only for status. There is no cream or paper tint and no second typeface.

### Colour tokens

The base is neutral, with one sage accent, because plain black and white looks bland. Sage appears only on the primary button, the logo, focus rings, the progress bar, the active card border, links, a switch that is on, the keyboard cursor, a drop zone's border, the active grid cell, the usage meters, and the "looks good" status. Backgrounds never use it.

The dark mode is pure neutral, apart from the sage accent. The PDF page stays white in dark mode, on the `#17171a` paper canvas, and is never inverted.

### Typography

- **Inter Variable** (`@fontsource-variable/inter`) for everything, wordmark included.
- The base size is 14px, with Inter's `cv11` and `ss01` features on. Tables use `tabular-nums`.

Each role is one class that sets size, line height, weight and tracking together.

| Class | Role | Size / line | Weight |
|---|---|---|---|
| `text-wordmark` | "sage" beside the logo | 17 / 17 | 600, tracking -0.01em |
| `text-display` | page heading ("Papers") | 22 / 28 | 600, tracking -0.01em |
| `text-title` | dialog, drawer and popover titles, big numbers | 16 / 24 | 600 |
| `text-value` | item label, extracted values | 14 / 20 | 500 |
| `text-body` | running text | 14 / 20 | 400 |
| `text-label` | field labels, tabs, toggles | 13 / 20 | 500 |
| `text-control` | text inside inputs, menus and table cells, dense secondary text | 13 / 20 | 400 |
| `text-caption` | hints, sources, times, table headers, the status line | 12 / 16 | 400 |

The `Button` component sets `text-control font-medium` rather than `text-label`, so a button given `text-caption` stays at 500.

No text is smaller than 12px.

### Spacing and shape

- Spacing uses Tailwind's 4px scale (`gap-2` is 8px). Half steps (2, 6 and 10px) align things inside a component. The named steps below are shared across screens.
  - `inset` (24px): from the edge of a bar, list, dialog or side panel to its content. Home rows, the top bar, the status line, dialogs and side panels use it.
  - `gutter` (32px): from the edge of the paper screen's panes, and the home page, to their content.
  - `control` (36px) and `control-sm` (32px): the height of buttons, inputs, selects, menu items and the segmented control, and of compact buttons in a card or row.
  - `icon` (18px): an icon in a full-size control. Icons beside text are 16px, and in captions 14px.
  - Margin cards pad 12px. The gap between them is 8px.
- Fixed heights that belong to one component stay in it: the top bar is 56px, the status line 40px, a tab or table row 44px, and a home row 64px.
- Radius, by what is rounded:
  - `control` 8px: buttons, inputs, menu items, rows;
  - `card` 10px: cards, dialogs, popovers, menus, toasts and drop zones;
  - `page` 4px: PDF pages;
  - `inline` 6px: a text button's focus ring, a disclosure trigger, a cell inside a card;
  - `bar` 4px: a loading text line, a chart column;
  - `mark` 3px: marked text, a legend swatch, an outline on the paper;
  - `highlight` 2px: a highlight box over the paper's text;
  - `full` for circles, pills and tracks.
- A panel docked beside the paper is `SidePanel` (440px).
- Shadows are barely there. `shadow-card` and `shadow-page` are `0 1px 3px rgba(0,0,0,.08)`, and `shadow-float` is for popovers and dialogs. `shadow-focus` rings a focused input, and `shadow-cursor` marks the row the keyboard is on. The active card uses a 1px sage border and no glow. In dark mode `shadow-card`, `shadow-page` and `shadow-float` are off, leaving borders, while `shadow-focus` and `shadow-cursor` stay.
- Motion is short and functional: card slides and expand (150 to 200ms, ease-out), a 700ms flash on the active highlight, the status line's progress bar, meter fills, the tab indicator, and the dialog, sheet and toast transitions. It respects `prefers-reduced-motion`.

## Principles

- Each screen has one filled primary action. Everything else is outline, ghost or a text button.
- Show where every value came from, so a scientist never has to trust a value blindly.
- Status is never colour alone. The tint comes with the problem in a few words on the card and sheet, and the word sits in the tooltip and `aria-label`.
- Empty, loading and error states are designed, not left blank.
- Every action a button does is also a `core.py` action with a CLI command and an API route.
