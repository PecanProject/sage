# Extract and watch a run

A user starts an extraction from a paper, from Home's inline Extract, or from the CLI. The run is taken on by the runner, one background process per data folder that runs `parallel_runs` runs at a time. A run that has to wait shows "Queued…". On the Paper screen a thin sage progress line (`status-progress`) runs under the top bar; there is no status text while it runs, and Stop sits in the run's panel (`run-stop`). The This run drawer (Runs › This run, or `details=1`) streams the steps, who drives the run (a model, an agent with its mark and model, or "From a terminal"), time, cost and turns for SAGE's own agent (checks, and cost when an agent reports one, for the others) and a feed of plain sentences over SSE. How each driver runs is in [drivers](./drivers.md). During a live run in Read mode on a wide window, the same details dock beside the paper instead. The drawer and the dock are the only places tokens appear. When the run ends, a toast says "Extraction finished: N items" and the screen switches to Check. A run that ends short gets an error toast for a failure, or a warning toast for a stop or a limit, with its carry-on action. An attempt that ends short never hides earlier data: the status line adds "Last attempt failed" (or "Last attempt stopped", or the limit) with its carry-on action and Details.

One rule (`carryOnLabel` in `web/src/lib/format.ts`) words the carry-on action everywhere: "Resume…" for a run that failed or was stopped (opens the Continue dialog as "Resume extraction"), "Continue" for one that ran out of budget with items (continues at once), and "Extract again…" for an ended run with no items that can't be resumed (opens the Extract dialog and closes the drawer). The drawer's footer offers "Continue…" on a run that finished with items. "Extract again" is only Home's inline button.

## Sub-features

- `extract-card` sits over a never-extracted paper with the Extract with select (`extract-card-model`: ready agents and your models) and **Extract data**. After a run that ended short with no data it shows the title ("Extraction failed", "Extraction stopped", or "Stopped at the turn limit" or cost limit), the reason (the error in a few words, else "Nothing found yet"), the carry-on action (`extract-card-retry`) and Details. When the provider refused the key or the model, it offers **Fix setup** (`extract-card-setup`) first. A run that finished with nothing leaves the plain card.
- `extract-dialog` (Runs › Extract again…, an "Extract again…" action, or `extract=1`, which doesn't open while a run is live) holds one Extract with select (`extract-model`), defaulting to `extract_with`, else the first of your models. Under "More options" it has a thinking effort (`extract-model-effort`, `data-value` the level shown): a model's own levels starting on its effort, or an agent's levels for its model, asked when the list opens, starting on the agent's effort. A model that doesn't think, or an agent model with no levels once asked, has no "More options". The footer reads "Stops at $X" for a model and "Stops after N minutes" for an agent. Then **Extract data**.
- `continue-dialog` defaults to the run's own driver: its agent (and model) or its model. A terminal's run defaults to what Extract uses. Guidance is required only to continue a finished run. There is no review-notes switch: the scientist's reviews reach the agent through check. Resume is offered only for a run SAGE's own agent drove; an agent's run that failed or stopped is continued.
- `agent-asks` shows in the drawer and the dock while `run.waiting` is set: the request's title with an amber hand ("Needs your OK" in its tooltip), the command in mono, and Deny (`agent-deny`) and Allow (`agent-allow`), which call `POST /api/papers/<id>/extract/answer`. The status line and Home read "Needs your OK" meanwhile. The real path is an ACP agent with `agents_ask` on (`sage config set agents_ask true`), started from the Extract dialog: the card shows when it asks for something outside the allowlist in [drivers](./drivers.md). That needs the agent signed in, spends on its account, and the agent may never ask. Otherwise use the render-only exception in [SKILL.md](../SKILL.md#evidence): a `running` run.json with `driver: "agent"`, `pid: 1` and `waiting` set, and an `agent.asked` event in its events.jsonl. It proves how the card looks, not that Allow or Deny reach a live agent.
- `extract-missing-key` keeps the start button disabled behind `setup-needed` ("Needs Anthropic's API key", or "Claude Code isn't signed in" for an agent, and a Set up link). If the server still answers `missing_key`, a toast with a "Set up" action shows instead of starting a run.
- `run-live` updates the status line and the drawer while the run works, including runs started from the CLI.
- `run-dock` docks the live run beside the paper in Read mode on a window at least 1024px wide. `[data-testid=run-dock]` shows, `menu-details` is disabled, and the dock's header has `run-stop`. On a narrower window Runs › This run (`menu-details`) opens the drawer, which has `run-stop` too. When the run ends the dock goes. A run that found items switches the paper to Check, and one that ended short with none on a paper with no data shows the ended `extract-card`.
- `run-drawer` shows model, time, cost and turns, then the tabs `tab-activity`, `tab-usage` and `tab-log`. Activity shows the feed as one fold per step (`[data-testid=step]`, with `data-state` done, active, failed, stopped or todo). The running step, a failed or stopped step, and Done start open, and the others start folded. Inside Extract, each model turn (`[data-testid=turn]`) holds a Thinking fold, what the model said, and its actions (`feed-line`, e.g. "Wrote records/sites.yaml"). Every `sage extract check` is a `feed-check` line ("Check found 3 problems, 1 note · 12 items" or "Check passed · 13 items", "Snapshot N" at its right when the files changed) with its first findings folded under it; it is the one timeline every driver shares. An agent's or a terminal's run has only the Extract and Done steps. `agent.asked` reads "Asked: <title>" with the command in mono, and your answer "You allowed it" or "You denied it". The feed follows new lines while the run is live. Scrolling up or opening a fold stops that and shows `[data-testid=jump-to-latest]`. Usage (`[data-testid=run-usage]`) holds, for SAGE's own agent, `meter-cost` and `meter-turns`; the token tiles (`run-tokens`), the input split, the per-turn chart (`turn-chart`, one button per request with a tooltip) and its table (`turn-table`, under "Every turn") only when the run used tokens; and always `run-facts` (with "Driven by"). A terminal's run shows only `run-facts`. Its numbers must match `run.json`'s `usage`. Log shows `raw-events`. `copy-log` copies it as JSON Lines, one line per event, so its line count matches the run's `events.jsonl`. Grant `clipboard-read` and `clipboard-write` to read the clipboard back. An ended run has its carry-on action in the drawer's footer (`resume-run`): "Resume…", "Continue", "Extract again…" or "Continue…".
- `run-resume-feed` marks a resume in the drawer. "Resumed with <model>" is a `feed-line` at the top of the new attempt inside the Extract step, after the earlier attempt's turns and lines. Every other restarted step shows only its latest attempt, except the run's opening lines ("Continued from an earlier extraction" and its guidance).
- `paper-latest-failed` keeps older data in view after a newer failure, with `[data-testid=last-failed]` in the status line. It also shows when the data's own run was stopped or hit its limit.
- `run-stop` writes a `stop` file in the run's folder. The runner cancels the run, which settles its draft and ends `interrupted`, and removes the file. A queued run with a stop request ends `interrupted` without starting.
- `run-cli` starts with `sage extract run`, watches with `sage logs <run> --follow`, and lists with `sage runs`. A Home or Paper screen that was already open picks the run up within about five seconds, with no reload.
- `run-document` keeps the document each run was checked against in `.sage/runs/<runId>/document.json`, written by each check and by done, so a later reparse of the paper never moves an older run's evidence boxes.
- `run-ends` never leaves a run `running`. An error ends it `failed` with the reason in `run.json` `error`, Ctrl-C ends it `interrupted`, and a `running` run whose pid is dead reads as `interrupted` in `sage runs`, the API and the UI. A `queued` run stays queued until a runner takes it on.
- `run-budget` stops at the cost limit with `budget_exhausted`. Its `usage` includes the response that crossed the limit. `run.json`'s `limit` and the `run.finished` event's `limit` read `cost` (or `turns`), and `sage show`, the run line and `sage logs` say "stopped at the cost limit". A turn the turn limit refuses logs no `llm.request`.

## How to get to it (user POV)

- On a never-extracted paper, use the card over the PDF.
- On Home, use a row's inline Extract. It starts with the default model and opens the paper.
- On a paper with data, choose Runs › Extract again….
- From the CLI, run `sage extract run <paperId>` or `sage extract run <paperId> --no-follow`.

## Driving it with verify-browser and cli

Preconditions:

- Baseline instance. A real key for a successful run (`up --key-from …`). Without one, every step below still runs, and the run fails at the first model call.

- **Card.** `browser_navigate $SAGE_VERIFY_URL/papers/Felipe-2010-Cultivar`. `[data-testid=extract-card]` shows `[data-testid=extract-card-model]` reading what Extract uses (e.g. "Claude Haiku 5.5", or "Claude Code" with its mark when `extract_with = "claude"`) and `[data-testid=extract-card-start]`.
- **Dialog.** `browser_navigate …/papers/Felipe-2010-Cultivar?extract=1`. `[data-testid=extract-dialog]` shows `[data-testid=extract-model]`, and with a thinking model or a ready agent picked `[data-testid=extract-model-effort]` under "More options" and `[data-testid=extract-limit]` reading "Stops at $1.00" with default settings. Pick `[data-testid=using-option][data-using=anthropic:claude-sonnet-5-5]` and click `[data-testid=start-extraction]` (`POST /api/runs` with `using`). The dialog closes, and `[data-testid=status-progress]` shows the step.
- **On disk.** `jq .extraction_model $SAGE_HOME/papers/Felipe-2010-Cultivar/.sage/runs/<runId>/run.json` prints `"anthropic:claude-sonnet-5-5"`.
- **CLI-started, page already open.** Open `…/papers/<paperId>` first and wait for it to settle. Then `$S/cli "$root" run extract run <paperId> --json`. Within about five seconds, without a reload, `[data-testid=status-progress]` appears (a fake key gives `[data-testid=last-failed]` or the failed `extract-card` instead, which proves the same pickup for free).
- **CLI-started, watched live.** `$S/cli "$root" run extract run Felipe-2010-Cultivar --no-follow --json` gives `.id`. Immediately open `…/papers/Felipe-2010-Cultivar` (a paper with no data opens in Read mode, so the run shows in `[data-testid=run-dock]`; on a paper with data, add `?mode=read`, or use `?details=1` for the drawer). Screenshots a few seconds apart show `[data-testid=step]` states advancing, `[data-testid=turn]` rows growing and `[data-testid=run-cost]` rising, all without a reload. Once the feed is taller than its panel, its scroller stays at the bottom. A real mouse wheel up (`page.mouse.wheel`, not `scrollTop`) keeps the position while turns arrive and shows `jump-to-latest`, and clicking that follows again. On Home the row's `[data-testid=paper-status]` has `data-state=live`. `$S/cli "$root" logs logs <id> --follow` returns when the run ends.
- **Outcome.** A toast reads "Extraction finished: N items", and the paper switches to Check. `sage runs --json` gives `.[0].status` `finished` or `budget_exhausted`.
- **Own document.** `ls $SAGE_HOME/papers/<paperId>/.sage/runs/<runId>/document.json` exists once the run has checked, and `curl $SAGE_VERIFY_URL/api/runs/<runId>/document` returns it (`parser_version` reads `pdftext-…+sage.N`).
- **Dead runner.** A `running` run whose pid is gone reads `interrupted`: `uv run python -c` on `sage.pipeline.run_state.live_status` with a `RunInfo` copy whose `pid` is a dead process shows it without touching `SAGE_HOME`. A `queued` copy stays `queued` with no runner. Never seed this by editing `run.json`.
- **Missing key.** On an instance without a key, `[data-testid=extract-card-start]` is disabled and `[data-testid=setup-needed]` reads "Needs Anthropic's API key" with Set up, and `sage extract run` exits 1 with `"kind": "missing_key"`. Its message names the provider, the field and the model, and points to the Manage page or `sage providers set anthropic api_key`. A provider you added says the same with its own title and the fields it lacks, for example an `openai` provider with no endpoint or key.
- **Failed with no data.** Save a fake key, start a run and wait. An error toast reads "Extraction failed" with a "Resume…" action. `[data-testid=extract-card]` has `data-state=failed`, with `[data-testid=extract-card-reason]`, `[data-testid=extract-card-retry]` reading "Resume…" and `[data-testid=extract-card-details]`. Clicking `extract-card-details` opens the drawer, where the Extract step has `data-state=failed` and holds the reason as a `feed-line` with `data-tone=bad`. `[data-testid=run-error]` in the header appears only for an error the log doesn't hold. On Home the row's `paper-status` reads "Failed" in the danger colour, with `row-retry` reading "Extract again".
- **Resumed.** Continue from the failed run. Click `extract-card-retry`: the URL gains `continue=<runId>`, and `[data-testid=continue-dialog]` reads "Resume extraction". Click `[data-testid=continue-start]`. Once it fails again, open the drawer. The Extract step's `feed-line`s read the first error, then "Resumed with claude-haiku-5-5", then the second error. `events.jsonl` holds two `run.started` events, the second with `"resumed": true`.
- **Stopped with no data.** Start a run with a real key and stop it at once with `run-stop` (in the dock or the drawer) and `stop-confirm`. A warning toast reads "Extraction stopped" with "Nothing found yet". The card shows the same with "Resume…", and Home's row reads "Stopped" in muted text. The run's `stop` file is gone once the runner has stopped it.
- **Failed after good data.** `[data-testid=last-failed]` reads "Last attempt failed" in the status line, with `[data-testid=status-retry]` reading "Resume…" and `[data-testid=status-details]`. On Home the row keeps "N to check" with `[data-testid=latest-failed-hint]`, whose `aria-label` is "Last attempt failed".
- **Queued.** With `sage config set parallel_runs 1`, queue two papers. The second reads "Queued…" in its row and status line, and `sage runs --json` gives it `status` `queued` until the first ends.
- **Live guard.** While a run is live, `…?extract=1` doesn't open `extract-dialog`.
- **Proof.** Screenshots of the status line and the dock or drawer early and late in one page load, plus `run.json` and the `events.jsonl` line count.

## Gotchas

- Live streaming is only proven when the page was open before the events arrived. Opening a finished run replays the log.
- Parsing is cached per paper, so a second run on the same paper reaches Extract within a second.
- Leave the dock or drawer on Activity (`[data-testid=tab-activity]`) for screenshots unless the shot is of Usage or Log.
- Toasts last a few seconds. To prove "Extraction finished", record toast text with a `MutationObserver` on `[data-sonner-toast]` installed before the run ends, rather than polling.
- The runner is detached and outlives `sage ui`. `down` stops it too, with SIGTERM, which stops its live runs the way Stop does.
- Keep the machine awake during a real run (`caffeinate -dimsu -t 3600` in the background). A sleeping laptop stalls the model call, and the run fails later with `ReadTimeout`.
- The cost limit is checked after each response, so one long turn can pass it. Pick Haiku and a small paper when spend matters, and compare `run.json` `usage.cost_usd` with the cap.
- A real Felipe run on Haiku takes a few minutes. Keep `max_cost_usd` at the default `$1` unless you mean to spend more.
