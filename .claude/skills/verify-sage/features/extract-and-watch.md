# Extract and watch a run

A user starts an extraction from a paper, from Home's inline Extract, or from the CLI. The run executes in a detached worker. On the Paper screen the status line shows a thin progress bar and the current stage ("Starting…", "Reading the paper…", "Reading tables…", "Extracting…" or "Checking…"). The This run drawer (Runs › This run, or `details=1`) streams the steps, model, time, cost, turns and a feed of plain sentences over SSE. During a live run in Read mode on a wide window, the same details dock beside the paper instead. The drawer and the dock are the only places tokens appear. When the run ends, a toast says "Extraction finished: N items" and the screen switches to Check. A run that ends short gets an error toast for a failure, or a warning toast for a stop or a limit, with its carry-on action. An attempt that ends short never hides earlier data: the status line adds "Last attempt failed" (or "Last attempt stopped", or the limit) with its carry-on action and Details.

One rule (`carryOnLabel` in `web/src/lib/format.ts`) words the carry-on action everywhere: "Resume…" for a run that failed or was stopped (opens the Continue dialog as "Resume extraction"), "Continue" for one that ran out of budget with items (continues at once), and "Extract again…" for an ended run with no items that can't be resumed (opens the Extract dialog and closes the drawer). The drawer's footer offers "Continue…" on a run that finished with items. "Extract again" is only Home's inline button.

## Sub-features

- `extract-card` sits over a never-extracted paper with a model select and **Extract data**. After a run that ended short with no data it shows the title ("Extraction failed", "Extraction stopped", or "Stopped at the turn limit" or cost limit), the reason (the error in a few words, else "Nothing found yet"), the carry-on action (`extract-card-retry`) and Details. A run that finished with nothing leaves the plain card.
- `extract-dialog` (Runs › Extract again…, an "Extract again…" action, or `extract=1`, which doesn't open while a run is live) holds the model, a thinking effort under "More options", the "Stops at $X" line and **Extract data**.
- `extract-missing-key` shows a toast with an "Open settings" action instead of starting a run.
- `run-live` updates the status line and the drawer while the run works, including runs started from the CLI.
- `run-dock` docks the live run beside the paper in Read mode on a window at least 1024px wide. `[data-testid=run-dock]` shows, the status line has no `status-details` link, and `menu-details` is disabled. On a narrower window the status line keeps `status-details`, which opens the drawer. When the run ends the dock goes. A run that found items switches the paper to Check, and one that ended short with none on a paper with no data shows the ended `extract-card`.
- `run-drawer` shows model, time, cost and turns, then the tabs `tab-activity`, `tab-usage` and `tab-log`. Activity shows the feed as one fold per step (`[data-testid=step]`, with `data-state` done, active, failed, stopped or todo). The running step, a failed or stopped step, and Done start open, and the others start folded. Inside Extract, each model turn (`[data-testid=turn]`) holds a Thinking fold, what the model said, its actions (`feed-line`) and a fold of checker problems (`[data-testid=problems]`). The feed follows new lines while the run is live. Scrolling up or opening a fold stops that and shows `[data-testid=jump-to-latest]`. Usage (`[data-testid=run-usage]`) holds `meter-cost` and `meter-turns`, the token tiles (`run-tokens`), the input split, the per-turn chart (`turn-chart`, one button per request with a tooltip) and its table (`turn-table`, under "Every turn"), `pass-table` and `run-facts`. Its numbers must match `run.json`'s `usage` and `table_usage`. Log shows `raw-events`. `copy-log` copies it as JSON Lines, one line per event, so its line count matches the run's `events.jsonl`. Grant `clipboard-read` and `clipboard-write` to read the clipboard back. An ended run has its carry-on action in the drawer's footer (`resume-run`): "Resume…", "Continue", "Extract again…" or "Continue…".
- `run-resume-feed` marks a resume in the drawer. "Resumed with <model>" is a `feed-line` at the top of the new attempt inside the Extract step, after the earlier attempt's turns and lines. Every other restarted step shows only its latest attempt, except the run's opening lines ("Continued from an earlier extraction" and its guidance).
- `paper-latest-failed` keeps older data in view after a newer failure, with `[data-testid=last-failed]` in the status line. It also shows when the data's own run was stopped or hit its limit.
- `run-cli` starts with `sage run`, watches with `sage logs <run> --follow`, and lists with `sage runs`. A Home or Paper screen that was already open picks the run up within about five seconds, with no reload.
- `run-document` keeps the document each run read in `runs/<runId>/document.json`, written after its table pass, so a later reparse of the paper never moves an older run's evidence boxes.
- `run-ends` never leaves a run `running`. An error ends it `failed` with the reason in `run.json` `error`, Ctrl-C ends it `interrupted`, and a `running` run whose worker pid is dead reads as `interrupted` in `sage runs`, the API and the UI.
- `run-budget` stops at the cost limit with `budget_exhausted`. Its `usage` includes the response that crossed the limit. `run.json`'s `limit` and the `run.finished` event's `limit` read `cost` (or `turns`), and `sage show`, the run line and `sage logs` say "stopped at the cost limit". A turn the turn limit refuses logs no `llm.request`.

## How to get to it (user POV)

- On a never-extracted paper, use the card over the PDF.
- On Home, use a row's inline Extract. It starts with the default model and opens the paper.
- On a paper with data, choose Runs › Extract again….
- From the CLI, run `sage run <paperId>` or `sage run <paperId> --no-follow`.

## Driving it with verify-browser and cli

Preconditions:

- Baseline instance. A real key for a successful run (`up --key-from …`). Without one, every step below still runs, and the run fails at the first model call.

- **Card.** `browser_navigate $SAGE_VERIFY_URL/papers/Felipe-2010-Cultivar`. `[data-testid=extract-card]` shows `[data-testid=extract-card-model]` reading the Settings model (e.g. "Haiku 5.5") and `[data-testid=extract-card-start]`.
- **Dialog.** `browser_navigate …/papers/Felipe-2010-Cultivar?extract=1`. `[data-testid=extract-dialog]` shows `[data-testid=extract-model]`, `[data-testid=extract-effort]` under "More options", and `[data-testid=extract-limit]` reading "Stops at $1.00" with default settings. Pick "Sonnet 5.5" and click `[data-testid=start-extraction]`. The dialog closes, and `[data-testid=status-live]` shows the step.
- **On disk.** `jq .extraction_model $SAGE_HOME/papers/Felipe-2010-Cultivar/runs/<runId>/run.json` prints `"anthropic:claude-sonnet-5-5"`.
- **CLI-started, page already open.** Open `…/papers/<paperId>` first and wait for it to settle. Then `$S/cli "$root" run run <paperId> --json`. Within about five seconds, without a reload, `[data-testid=status-live]` appears (a fake key gives `[data-testid=last-failed]` or the failed `extract-card` instead, which proves the same pickup for free).
- **CLI-started, watched live.** `$S/cli "$root" run run Felipe-2010-Cultivar --no-follow --json` gives `.id`. Immediately open `…/papers/Felipe-2010-Cultivar` (a paper with no data opens in Read mode, so the run shows in `[data-testid=run-dock]`; on a paper with data, add `?mode=read`, or use `?details=1` for the drawer). Screenshots a few seconds apart show `[data-testid=step]` states advancing, `[data-testid=turn]` rows growing and `[data-testid=run-cost]` rising, all without a reload. Once the feed is taller than its panel, its scroller stays at the bottom. A real mouse wheel up (`page.mouse.wheel`, not `scrollTop`) keeps the position while turns arrive and shows `jump-to-latest`, and clicking that follows again. On Home the row's `[data-testid=paper-status]` has `data-state=live`. `$S/cli "$root" logs logs <id> --follow` returns when the run ends.
- **Outcome.** A toast reads "Extraction finished: N items", and the paper switches to Check. `sage runs --json` gives `.[0].status` `finished` or `budget_exhausted`.
- **Own document.** `ls $SAGE_HOME/papers/<paperId>/runs/<runId>/document.json` exists once the table pass is done, and `curl $SAGE_VERIFY_URL/api/runs/<runId>/document` returns it (`parser_version` reads `pdftext-…+sage.N`).
- **Dead worker.** A `running` run whose pid is gone reads `interrupted`: `uv run python -c` on `sage.core._live_status` with a `RunInfo` copy whose `pid` is a dead process shows it without touching `SAGE_HOME`. Never seed this by editing `run.json`.
- **Missing key.** On an instance without a key, `[data-testid=extract-card-start]` shows a toast naming the missing key, and `sage run` exits 1 with `"kind": "missing_key"`.
- **Failed with no data.** Save a fake key, start a run and wait. An error toast reads "Extraction failed" with a "Resume…" action. `[data-testid=extract-card]` has `data-state=failed`, with `[data-testid=extract-card-reason]`, `[data-testid=extract-card-retry]` reading "Resume…" and `[data-testid=extract-card-details]`. Clicking `extract-card-details` opens the drawer, where the Extract step has `data-state=failed` and holds the reason as a `feed-line` with `data-tone=bad`. `[data-testid=run-error]` in the header appears only for an error the log doesn't hold. On Home the row's `paper-status` reads "Failed" in the danger colour, with `row-retry` reading "Extract again".
- **Resumed.** Continue from the failed run. Click `extract-card-retry`: the URL gains `continue=<runId>`, and `[data-testid=continue-dialog]` reads "Resume extraction". Click `[data-testid=continue-start]`. Once it fails again, open the drawer. The Extract step's `feed-line`s read the first error, then "Resumed with Haiku 5.5", then the second error. `events.jsonl` holds two `run.started` events, the second with `"resumed": true`.
- **Stopped with no data.** Start a run with a real key and stop it at once with `status-stop` and `stop-confirm`. A warning toast reads "Extraction stopped" with "Nothing found yet". The card shows the same with "Resume…", and Home's row reads "Stopped" in muted text.
- **Failed after good data.** `[data-testid=last-failed]` reads "Last attempt failed" in the status line, with `[data-testid=status-retry]` reading "Resume…" and `[data-testid=status-details]`. On Home the row keeps "N to check" with `[data-testid=latest-failed-hint]`, whose `aria-label` is "Last attempt failed".
- **Live guard.** While a run is live, `…?extract=1` doesn't open `extract-dialog`.
- **Proof.** Screenshots of the status line and the dock or drawer early and late in one page load, plus `run.json` and the `events.jsonl` line count.

## Gotchas

- Live streaming is only proven when the page was open before the events arrived. Opening a finished run replays the log.
- The parse and table stages are cached per paper, so a second run on the same paper reaches Extract within a second.
- Leave the dock or drawer on Activity (`[data-testid=tab-activity]`) for screenshots unless the shot is of Usage or Log.
- Toasts last a few seconds. To prove "Extraction finished", record toast text with a `MutationObserver` on `[data-sonner-toast]` installed before the run ends, rather than polling.
- Keep the machine awake during a real run (`caffeinate -dimsu -t 3600` in the background). A sleeping laptop stalls the model call, and the run fails later with `ReadTimeout`.
- The cost limit is checked after each response, so one long turn can pass it. Pick Haiku and a small paper when spend matters, and compare `run.json` `usage.cost_usd + table_usage.cost_usd` with the cap.
- A real Felipe run on Haiku takes a few minutes. Keep `max_cost_usd` at the default `$1` unless you mean to spend more.
