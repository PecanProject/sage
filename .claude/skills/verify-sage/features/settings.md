# Settings

Settings is a page (`/settings`, the ⚙ in the top bar). It opens with General (the cost limit per paper, Appearance, and a Manage row that links to the Manage page, "Agents, models and providers ›"), then a section for each group of settings in the schema, each with the group's description and one row per field: its title, its description under it, a control, and a reset icon when the value differs from the default. Agents, providers, your models, what Extract uses (`extract_with`) and each model's and agent's effort are not here. They live on the Manage page (`/manage`, the chip icon, titled "Manage"), where each control saves at once. On the Settings page, edits are a draft. While there are any, a bar sticks to the bottom (`settings-save-bar`) with "Unsaved changes", Discard and Save. Save writes only the changed fields to `config.toml` (mode 0600) and shows a "Settings saved" toast, and the page stays open. A value set by an environment variable is read-only and names the variable. The CLI edits the same settings with `sage config`, the providers with `sage providers`, and the models with `sage models`.

## Sub-features

- `settings-basic` covers the cost limit and Appearance (System, Light or Dark).
- `settings-groups` shows one section per group after General, each with its description from the schema's `groups`. There is no collapsed Advanced section.
- `settings-manage-link` (`[data-testid=settings-manage-link]`) reads "Agents, models and providers" and opens `/manage`.
- `save-settings` (`[data-testid=save-settings]`) is the one Save. It writes only changed fields, and the bar isn't there when the draft is empty. `discard-settings` puts the saved values back.
- `settings-reset` (`[data-testid=setting-reset-<field>]`) puts one field back to its default in the draft.
- `settings-lock` shows an env-set field as read-only with "Set by SAGE_…".
- `settings-strip` shows `[data-testid=setup-strip]` under the top bar only when nothing can extract: what Extract uses by default can't start (an agent that isn't ready, or a model whose provider lacks a field) and the SAGE skill isn't installed. It reads "No way to extract yet" with a "Set up" link. It is hidden on `/manage` and on Home's first screen, which says the same.
- `settings-errors` shows the server's message under each invalid field, never the browser's bubble (the form has `noValidate`). Editing the field clears its error, and the bar names the fields that failed.
- `settings-cli` covers `sage config list|get|set`. `config get` prints the bare JSON value (`40`, `null`, `false`). `config set` refuses `providers` and `models`, with a hint at the right command, and any key that isn't a setting.
- `manage-page` (`[data-testid=manage-page]`, headed "Manage skills, agents & models") has four sections in order: SAGE skill, Agents, Your models, Providers. **Agents** (`agents`): one `agent-row` per agent (`data-agent=<id>`) with its brand mark, title, `data-state` (ready, not_signed_in or not_installed), a state shape (`agent-state`, also with `data-state`; the word only in its tooltip and `aria-label`) only when it isn't ready, the fix (install or sign-in command, mono, in caption text under the title; a line that is a command itself has a copy icon, `agent-fix-copy`) when not ready, "Default" and an arrow in the margin before the row (`agent-default`) when Extract uses it, a model select (`agent-model`) and an effort select (`agent-effort`, `data-value` the saved level or empty for "Default effort"; options `agent-effort-option`), both only when the agent is ready, and an `agent-menu` with Use by default (`agent-use`). Opening either select asks the agent (`GET /api/agents/{id}/offer`, `?model=` for the effort); the effort select is gone once the agent says its model has no levels (Codex on `gpt-5.5`). Picking a level writes `effort` under `[agents.<id>]` in `$SAGE_CONFIG` (`PUT /api/agents/{id}`); picking a model writes `model` there and clears an effort the new model lacks. **Your models** (`your-models`, one `model-row` each, with the provider's mark, `model-roles`, "Default" and an arrow in the margin before the row, on the one Extract uses, `model-price` in the line under it after the provider, an effort select (`model-effort`, `data-value` its level, options `model-effort-option`, absent for a model that doesn't think) that saves at once to the model's `[[models]]` entry (`POST /api/models/effort`), and a `model-menu` of Use by default (`model-use`), Set price… and Remove). The model and effort selects in these rows are quiet triggers (value and caret, a border only on hover or focus), and the effort columns of both lists line up. Then `add-model`, a quiet button under the list, then **Providers** (`#providers`): one `provider` row per provider (`data-provider=<id>`) with its brand mark, its host and masked key in the line under the title, `key-check` once it has what it needs (nothing there before), and `provider-setup` ("Set up", or "Change" once it has what it needs, "Done" while open), which opens its fields under the row (`provider-fields`, the URL gains `provider=<id>`); then `add-provider`, a quiet button under the list. **SAGE skill** comes first: `skill-row` (`data-state` current, outdated or missing) holds the `skill-command` (`sage skill install`, mono after a "$" prompt on a tinted strip, with a copy icon `skill-command-copy` inside it) and Install or Update (`skill-install`), or `skill-state` reading Installed, whose tooltip lists the two skill folders. The CLI side of agents and the skill is in [drivers](./drivers.md).
- `models-provider-fields` edits a provider's fields once its `provider-setup` opens them: a text field (`field-<name>`, with `field-save-<name>` once it differs), a secret field (`secret-<name>` masked, `secret-change-`, `secret-remove-`, `secret-input-`, `secret-save-` and `secret-keep-<name>`), and the fields under More. Every save is its own request. An env-set field reads "Set by …" in `field-<name>`.
- `manage-provider-check` shows nothing at the right of a provider that lacks a field (its `provider-setup` reads "Set up"), and `key-check` once it has what it needs: "Checking", then `data-ok=true` and nothing visible (its screen-reader text reads "Works · N models, M can extract"), or `data-ok=false` with the provider's reason plus `key-recheck` ("Check again"). It asks the provider which models it offers, which costs nothing.
- `models-add-provider` (`add-provider` → `?add=provider`, `add-provider-dialog`) takes a Kind (`add-provider-kind`), a Name (`add-provider-name`), an ID (`add-provider-id`, a slug of the name until edited) and the kind's fields (`add-provider-<field>`). `add-provider-save` adds it and opens its fields. `provider-remove`, under an added provider's open fields, removes it.
- `models-add-model` adds a model from the combobox (`add-model-list`, `add-model-option[data-model=…]`): a listed model, a `provider:name` typed in ("By name"), one that can't call tools (disabled), or one SAGE has no price for.
- `models-price` (`?price=<model id>`, `price-dialog`) takes your price per million tokens (`price-input`, `price-output`, `price-save`), for a model SAGE can't price and through **Set price…** on any row. A **Cache prices** fold (`price-cache`) takes `price-cache-read` and `price-cache-write`, both or neither; left empty, SAGE uses the model's own cache discount, else the input price.
- `models-cli` covers `sage providers` (list, `kinds`, `add`, `set`, `remove`), and `sage models` (list, `available [PROVIDER]`, `add ID [--price IN OUT]`, `remove ID...`).

## How to get to it (user POV)

- Click ⚙ in the top bar for Settings.
- Click the Manage button (a chip icon) in the top bar, or "Set up" in the setup strip or beside a start button, for the Manage page.
- Run `sage config …`, `sage providers …` or `sage models …` in a terminal.

- Baseline instance, no key.

## Gotchas

- `model-effort`, `agent-effort`, the dialogs' `*-effort`, the Kind select, `agent-model` and every Extract with control (`extract-model`, `extract-card-model`, `continue-model`, `extract-all-model`) are Base UI Selects, not `<select>`. Click the trigger, then the `option` role by name, or `[data-testid=using-option][data-using=<agent or provider:name>]`. The only combobox is Add a model, and its list is `[data-testid=add-model-list]`.
- Provider test ids carry the field's name, not the provider's: `secret-input-api_key`, `field-base_url`. Every provider row has its own, so scope them with `[data-provider=<id>]`. Text inputs also have ids `#provider-<id>-<field>`.
- A provider that lacks a field shows no `key-check` and no words at the right. `key-check` appears only once the provider has everything it needs.
- A text field's Save appears only once its value differs from the saved one. A secret field's Remove saves at once, with no confirmation.
- Settings fields on the Settings page are `#setting-<field name>`. A group's section is always open, so there is nothing to expand.
- `home` is a Paths setting. Changing it on an `up` instance has no effect, because `up` exports `SAGE_HOME`, which wins.
- Never type the user's real key into a verification instance. Use `up --key-from` to copy it.
- An empty value restores the default (`sage config set <name> ""`), and clears a provider field (`sage providers set <id> <field> ""`).
- A provider check is reused for five minutes, so after changing a provider outside the page, click `key-recheck`.
